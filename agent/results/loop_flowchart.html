How the optimization agent works

One task at a time, the model proposes a rewritten CHEHAB kernel, CHEHAB and SEAL run it on encrypted data, and the result is fed back. Eight attempts per task; only a kernel that is correct and confirmed faster becomes the new best.

Step by step

  1. Task given. The model gets the operator's description, its inputs and outputs, the CHEHAB rules for the scheme, measured operation costs, and the baseline kernel with its metrics.
  2. Proposal. It answers with a complete rewritten kernel. No tools, no file access: just code.
  3. Safety check. The kernel is rejected before compiling if it is not plain CHEHAB code.
  4. CHEHAB compiles. CHEHAB turns the kernel into SEAL code and adds the bookkeeping itself. A scale mismatch or an unsupported construct stops here, and the error names the two values that clashed.
  5. Encrypted test. The generated program encrypts the test inputs, runs, and decrypts. The outputs must match values computed independently in plain arithmetic, on every test case.
  6. Strict selection. A correct kernel is compared by circuit shape first. If it is new, it is timed against the current best back and forth. It becomes the best only if it is at least 3% faster and wins most rounds, so timing noise cannot count as a speedup.
  7. Feedback. Whatever happened is reported back, and the model tries again with the full history in view, up to 8 times.

What each part is

Agent

Claude (Haiku, Sonnet or Opus), called through the Claude Code CLI on the team's subscription. It writes kernel code only.

Environment

CHEHAB, the FHE compiler, plus Microsoft SEAL for the encrypted run. Deterministic; no model involved.

Tasks

29 operators: 26 CKKS (activations, add, multiply, batchnorm, extraction, embedding) and 3 BFV (linear, conv2d, avgpool2d). Each starts from the repository's own benchmark kernel.

Result per task

Baseline time, best time, confirmed speedup, levels and operation counts before and after, how many of the 8 proposals were correct.

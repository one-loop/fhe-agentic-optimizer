# CKKS operators 7-9 through CHEHAB: ReLU, Add, Multiply

Each operator is a CHEHAB DSL program compiled by `Compiler::compile` and `Compiler::gen_he_code`, then built and run on encrypted inputs. Shared CKKS parameters: N = 32768, coeff modulus {60, 40 x 10, 60}, scale 2^40 (10 levels).

**8. Add** (`benchmarks/elementwise_ckks`, no level consumed)

- `add_ckks`: ciphertext + ciphertext (`evaluator.add`).
- `add_plain_ckks`: ciphertext + plaintext slot vector (`add_plain`).
- `add_scalar_ckks`: ciphertext + plaintext scalar (`add_plain` of a scalar-encoded constant).

**9. Multiply** (`benchmarks/elementwise_ckks`, one level consumed)

- `mul_ckks`: ciphertext x ciphertext with relinearization (`multiply`, `relinearize`, `rescale_to_next`).
- `mul_plain_ckks`: ciphertext x plaintext slot vector (`multiply_plain`, `rescale_to_next`).
- `mul_scalar_ckks`: ciphertext x plaintext scalar (same, scalar-encoded constant).

A scalar is a plaintext input given as one value in the io file; the generated `fhe()` encodes it with SEAL's scalar encode (`ckks_encode`), a constant in every slot. The DSL program of the plain and scalar variants is the same: CHEHAB's CKKS path does not support real-valued IR constants, so the distinction is made at the input boundary.

**7. ReLU** (`benchmarks/relu_ckks`, 10 levels)

- `relu_ckks`: ReLU(x) = x * (1 + sign(x / 4)) / 2 on [-4, 4], with sign approximated by a composite of three degree-7 odd minimax polynomials (stage-wise Remez, Lee et al., IEEE TDSC 2021). `fit_composite_sign.py` fits them (committed in `relu_sign_coeffs.json`; each stage verified to equioscillate). Each stage costs 3 levels through a baby-step/giant-step split; the final x * h costs 1.
- Approximation quality (fitting grid of 400001 points): max error 0.0118, located near 0; 2.3e-6 for |x| >= 0.25.
- `chebyshev_relu_d7_ckks` and `chebyshev_relu_d2_ckks` are single Chebyshev least-squares fits kept as low-depth baselines (max error 0.17 and 0.38).

**Correctness.** PASS requires the decrypted output within 1e-6 of the same computation in plaintext (numpy for add/multiply; the plaintext composite polynomial for ReLU) in every measured run, and the expected levels. Approximation error vs the true ReLU is reported separately.

CKKS-specific: **FHE max abs error** is decrypted output vs the same computation in plaintext (PASS requires <= 1e-06 in every measured run and the expected levels); **max_fit_error** is the committed fitting-grid error of the Chebyshev coefficient set and **approx. error** the plaintext polynomial vs the true activation on the case's test points (approximation error, kept separate from FHE error); **levels** = start - end chain index.

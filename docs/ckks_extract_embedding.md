# CKKS operators 11-12 through CHEHAB: embedding and extraction

Each case is a CHEHAB DSL program compiled by `Compiler::compile` and
`Compiler::gen_he_code`, then built and run on encrypted CKKS inputs. The
expected outputs are computed independently with NumPy and compared with the
decrypted results.

This baseline covers `TableMult`, `TableMultConsolidate` (reported as
`embedding`), `Extract`, `ExtractLinear`, and `ExtractSparse`. The fixed
`ExtractSparse` case exercises the boundary where removing the dense prefix
reduces the ciphertext chunk count. The Exact Indicator Function (EIF) is not
yet covered, so this is not the complete privacy-preserving embedding pipeline.

PASS requires both the expected level consumption and maximum absolute error
at most `1e-4`. The repository's direct SEAL CKKS benchmark uses this same
conservative tolerance. These rotation-and-reduction operators exceeded the
stricter `1e-6` default in an initial smoke run (worst observed error
`3.40e-5`), while remaining below `1e-4`; the selected bound and raw errors are
therefore recorded rather than hidden by changing the runner default.

Generated by `run_benchmarks.py` at commit 2012ffa (with local changes) on Darwin arm64, Apple clang version 17.0.0 (clang-1700.6.3.2), Microsoft SEAL 4.1.

Command: `python run_benchmarks.py --scheme ckks --seal-prefix /private/tmp/seal-install --benchmarks extract_ckks extract_linear_ckks extract_sparse_ckks table_mult_ckks embedding_ckks --compile-runs 3 --warmup 1 --repeats 3 --eval-repeats 3 --ckks-tolerance 1e-4 --output results/ckks_extract_embedding.csv --markdown docs/ckks_extract_embedding.md`

Timing: compile phase median of 3 runs; generated program 1 warmup + 3 measured runs, median (min-max) of CHEHAB's end-to-end execution time (parse inputs + encode + encrypt + evaluate). CKKS also reports an evaluation-only median (fhe() alone, 1 warmup + 3 runs per process, median over the measured processes). All times in ms.

BFV and CKKS rows use different encryption parameters (see the parameters column): **do not compare latency across the two tables.**

CKKS-specific: **FHE max abs error** is decrypted output vs the same computation in plaintext (PASS requires <= 0.0001 in every measured run and the expected levels); **max_fit_error** is the committed fitting-grid error of the Chebyshev coefficient set and **approx. error** the plaintext polynomial vs the true activation on the case's test points (approximation error, kept separate from FHE error); **levels** = start - end chain index.

Shared: operation counts are `evaluator.<method>` calls in the generated `fhe()` (add_p = add_plain, sub_p = sub_plain, mul_p = multiply_plain, relin = relinearize, mod_sw = mod_switch_to_next); (depth, xdepth) are the CHEHAB Quantifier's (depth counts operations on the longest path, xdepth counts multiplications including ciphertext-plaintext ones). Field definitions: `docs/benchmark_results.md`.
